# Private read-only metadata preflight (proposal; not deployed)

Base: #100, `90da78f0fa65c99a81e756cb9964c4f41e52ae80`. Existing files remain unchanged. This diagnostic does not create a database, role, grant, schema, marker or service, and never authorizes initialization or retry. Proposed fixed names are `lzr_h100_demo`, `lzr_h100_owner`, `lzr_h100_app`.

The explicit operational entry is `node --experimental-strip-types scripts/private-db-preflight.mjs --start`. It checks the existing synthetic launcher/artifact guards, runs one disposable diagnostic child, waits for close, emits one sanitized blocked report and starts the original synthetic web server with its original URL/behavior. Only the diagnostic is read-only. Normal authenticated application writes remain possible as before. Nothing enables this command by default; configuration/deployment requires separate authorization. Do not configure the standalone diagnostic (without `--start`, exit 2) as a restarting web service.

Use the existing `SYNTHETIC_RO_INSPECTION_*` absolute not-before/expiry window (at most ten minutes), `MODE=inspect`, and exact expected host/database/user/OID pins, plus `PRIVATE_DB_PREFLIGHT_ENABLED=true`. Missing/false private opt-in skips the diagnostic. No OID auto-discovery or promotion. Existing synthetic/external-integration guards apply. The transport remains the explicitly private TCP port 5432, `ssl:false` contract; this is not a TLS downgrade or permission to use a public endpoint. No remote configuration was applied.

SQL is fixed in `lib/platform/private-db-preflight.mjs`: a repeatable-read READ ONLY transaction, pg_catalog search path, 3-second statements, 1-second lock timeout. Parent kills child by 20 seconds/window expiry; child closes its client before the only IPC result. Parent emits only after child closes; duplicate/invalid IPC, cleanup failures and timeouts override observations. Stdout/stderr of the child are discarded. OS-level termination remains dependent on normal kernel process handling.

Capabilities are only observed `pg_roles.rolcreatedb/rolcreaterole` metadata, not execution authority. Names must be absent. PUBLIC CONNECT/TEMP checks conservatively include every existing database with `datallowconn`, including templates/system databases: a PUBLIC CONNECT result blocks strict no-access planning. Revoking a future role's direct grant would not override PUBLIC. This does not mutate any old ACL. PUBLIC schema/object ACL checks are limited to the currently connected database's public schema and relation/routine grants; other schemas, column ACLs, default privileges, memberships, future effective permissions and other databases' objects remain unverified. A nonexistent proposed role cannot have its effective grants tested. No absolute isolation claim is possible on this shared cluster.

Capacity is only the current database's `pg_database_size` bucket (<1 GiB, 1–10 GiB, >=10 GiB) and current database's `pg_stat_database.numbackends` bucket (<10, 10–49, >=50). Null/malformed values fail closed. These are observations, not headroom: cluster disk, memory, workload and available connection capacity remain unknown. No per-database size sweep occurs. `capacityVerified`, `remoteExecutionAllowed`, `initializationAllowed`, `retryAllowed`, `credentialsVerified` and `attemptReconciled` are always false; even clean metadata is `blocked/capacity-unverified`. Output contains no names, OIDs, secrets, content, exact sizes/counts or raw errors.

Validation: `node --experimental-strip-types --test tests/private-db-preflight.test.mjs`. Explicit local-only PG17 verification: `node tests/manual/private-preflight-pg17.mjs --run`, requiring the existing installed locked pg 8.22.0 and cached pinned official PG17 image. It never pulls/builds, uses network-none/new tmpfs DB and credentials, readonly mounts, no ports, and verifies cleanup. It checks default PUBLIC CONNECT, role/database-name collisions, mismatched OID, and absent capability metadata. Only its disposable fixture setup changes ACLs/roles; after clearing that fixture PUBLIC ACL it confirms capacity remains unverified. The diagnostic connection stays READ ONLY. It does not prove remote authorization or full ACL permutations. Evidence is written under `/workspace/evidence/private-preflight-pg17/`; no existing dataset is used.
